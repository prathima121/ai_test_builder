# AI Test Builder - Deployment Guide

This guide covers deploying the AI Test Builder monorepo across multiple services.

## Project Structure
- **Frontend**: `apps/web` (Next.js) → Vercel
- **Backend API**: `apps/server` (Node.js + Express) → Railway/Fly.io/Render
- **Worker**: `apps/worker` (BullMQ) → Railway/Fly.io/Render
- **Database**: PostgreSQL (Supabase/Railway)
- **Cache**: Redis (Railway/Cloud Redis)

## 🚀 Quick Deployment

### Prerequisites
1. GitHub account (✅ already set up)
2. Vercel account (free)
3. Railway/Fly.io account (for backend)
4. OpenRouter API key (for LLM)

---

## 1️⃣ Deploy Frontend to Vercel (5 minutes)

### Step 1: Connect to Vercel
1. Go to https://vercel.com/new
2. Sign in with GitHub
3. Select **prathima121/ai_test_builder** repository
4. Click "Import"

### Step 2: Configure Build Settings
- **Framework Preset**: Next.js
- **Root Directory**: `apps/web` (if not auto-detected, set this)
- **Build Command**: `npm run build -w @aitb/web`
- **Output Directory**: `.next`
- **Install Command**: `npm install`

### Step 3: Add Environment Variables
In Vercel project settings → Environment Variables, add:
```
NEXT_PUBLIC_API_URL=https://your-backend-url.railway.app
```

### Step 4: Deploy
Click "Deploy" - Vercel will automatically build and deploy

**Your Frontend Live URL**: `https://your-project.vercel.app` ✅

---

## 2️⃣ Deploy Backend to Railway (10 minutes)

### Step 1: Set Up Railway Project
1. Go to https://railway.app
2. Sign in with GitHub
3. Click **+ New Project** → **Deploy from GitHub repo**
4. Select **prathima121/ai_test_builder**

### Step 2: Add PostgreSQL Database
1. In Railway dashboard, click **+ Add**
2. Select **PostgreSQL**
3. Railway will auto-generate `DATABASE_URL`

### Step 3: Add Redis
1. Click **+ Add** again
2. Select **Redis**
3. Railway will auto-generate `REDIS_URL`

### Step 4: Configure Backend Service

#### Create `apps/server/Dockerfile`:
```dockerfile
FROM node:20-alpine

WORKDIR /app

# Install dependencies
COPY package*.json ./
COPY apps/server/package*.json ./apps/server/
COPY packages/shared/package*.json ./packages/shared/
RUN npm install --legacy-peer-deps

# Copy source
COPY tsconfig.base.json ./
COPY apps/server ./apps/server
COPY packages/shared ./packages/shared

# Build
WORKDIR /app/apps/server
RUN npm run build

# Generate Prisma Client
RUN npm run prisma:generate

EXPOSE 4000

CMD ["npm", "start"]
```

#### Create `apps/server/.dockerignore`:
```
node_modules
npm-debug.log
.git
.env
dist
```

#### In Railway Dashboard:
1. Select the backend service
2. Go to **Settings** → **Deploy**
3. **Dockerfile Path**: `apps/server/Dockerfile`
4. **Root Directory**: `.` (monorepo root)

### Step 5: Set Environment Variables in Railway
In Railway Dashboard → project → Variables, add:
```
PORT=4000
QUEUE_ENABLED=true
OPENAI_API_KEY=your_key_from_openrouter
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_MODEL=openai/gpt-4o-mini
NEXT_PUBLIC_API_URL=https://your-backend.railway.app
```

- `DATABASE_URL` and `REDIS_URL` are auto-generated ✅

### Step 6: Deploy
Click **Deploy** - Railway will build and run your backend

**Your Backend Live URL**: `https://your-backend.railway.app` ✅

## 3️⃣ Deploy Worker to Railway (same project)

### Option A: Same Service (Recommended for small projects)
Keep worker in the same Railway service as backend. It will use the same Redis queue.

### Option B: Separate Service
Create another service in the same Railway project for the worker:

#### Create `apps/worker/Dockerfile`:
```dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./
COPY apps/worker/package*.json ./apps/worker/
COPY packages/shared/package*.json ./packages/shared/
RUN npm install

COPY tsconfig.base.json ./
COPY apps/worker ./apps/worker
COPY packages/shared ./packages/shared

WORKDIR /app/apps/worker
RUN npm run build

CMD ["npm", "start"]
```

#### In Railway:
1. **+ New Service** → **Deploy from GitHub repo**
2. Same repo, same PostgreSQL, same Redis
3. Set **Dockerfile Path**: `apps/worker/Dockerfile`
4. Add same environment variables

## 4️⃣ Environment Variables Reference

### Frontend (`apps/web`)
```env
NEXT_PUBLIC_API_URL=https://your-backend.railway.app
```

### Backend & Worker (`apps/server`, `apps/worker`)
```env
# Database (auto-generated by Railway)
DATABASE_URL=postgresql://user:pass@host:5432/db

# Redis (auto-generated by Railway)
REDIS_URL=redis://default:pass@host:6379

# LLM API
OPENAI_API_KEY=sk-xxxxx  # Get from https://openrouter.ai
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_MODEL=openai/gpt-4o-mini  # or your preferred model

# Server
PORT=4000
QUEUE_ENABLED=true

# Frontend Integration
NEXT_PUBLIC_API_URL=https://your-backend.railway.app
```

## 🛠️ Troubleshooting

### Vercel Build Fails
- Check build logs: Vercel Dashboard → Deployments → Failed deployment
- Ensure `vercel.json` points to correct root directory
- Verify `apps/web/.next` is in `.gitignore`

### Railroad/Railway Database Connection
- Verify `DATABASE_URL` is set correctly
- Run Prisma migrations:
  ```bash
  npm run db:generate
  npm run db:migrate
  ```

### Worker Not Processing
- Verify `QUEUE_ENABLED=true` in environment
- Check Redis connection with `REDIS_URL`
- View worker logs in Railway/Fly.io dashboard

### API Calls 404/CORS Issues
- Verify `NEXT_PUBLIC_API_URL` matches backend URL
- Add CORS headers in backend (already in code)
